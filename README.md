# G9N9N Bluetooth keyboard bridge

Run `./g9n9n-bridge.py` on a Linux system with BlueZ, Python D-Bus/GLib bindings, and python-evdev installed. The user needs access to the system D-Bus and `/dev/uinput`; the remote must already be paired and known to BlueZ. The bridge reconnects and resubscribes when possible.

By default the bridge finds a known BlueZ device named or aliased `G9N9N`, falling back to the previously configured address `FF:32:3A:75:83:0D`. Set another name with `--name`, or select an address explicitly with `--address AA:BB:CC:DD:EE:FF`. The remote must already be paired and known to BlueZ; the bridge does not scan or pair devices. By default the bridge looks for a notification characteristic with HID service UUID `00001812-0000-1000-8000-00805f9b34fb` and Report UUID `00002a4d-0000-1000-8000-00805f9b34fb`. Override them with `--service-uuid` and `--characteristic-uuid` if necessary. For the previously configured device, the original `service0023/char002a` report is selected automatically when present. If multiple characteristics match and that report is unavailable, the log lists their paths: select the consumer report with `--characteristic-path /org/bluez/...`. This explicit path can change after device re-pairing or GATT changes; update it when needed.

A held key is released after 10 seconds without another report. Use `--key-timeout SECONDS` to change this, or `--key-timeout 0` to disable the timeout. Some remotes send no further reports during a long press, so increase or disable the timeout if long presses are cut short. Use `--log-level DEBUG`, `INFO`, `WARNING`, or `ERROR` to adjust logging.

Run the simulated behavior tests with `python3 -m unittest discover -s tests -v`. Hardware-specific UUID selection and Bluetooth reconnection should also be verified with the actual remote.

The extra buttons assume the reported codes are YouTube (`0x0077`), Netflix (`0x0078`), power (`0x019e`), and source (`0x0189`), respectively. YouTube and Netflix open their websites using `xdg-open`; when started through sudo they run as the invoking user. The power button sends the desktop's screen-lock key, and source sends the display-mode-switch key. The desktop environment must support those keys; switching the computer's display mode does not change a monitor's physical input. Opening websites requires a graphical user session and `xdg-open`.

To experimentally stop G9N9N ATVV 1.0 voice sessions as soon as the assistant button starts one, run `sudo python g9n9n-bridge.py --cancel-voice`. This disables the remote's voice audio while enabled and may reduce delays to other buttons; improvement has not yet been verified on hardware. The bridge discovers the ATVV service by UUID, subscribes to control notifications, and sends MIC_CLOSE with the reported stream ID. It does not implement microphone audio, speech recognition, or an assistant. Do not use this option alongside software using the remote's microphone. ATVV message layout was checked against [ATVVoice](https://github.com/b0o/ATVVoice/blob/main/src/protocol/v10.rs).


The experimental assistant + volume Page Up/Down mapping is disabled because the remote can buffer normal key reports during the voice session.
